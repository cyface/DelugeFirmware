# Chord libraries

The chord library keyboard layout can load its chord set from XML files on the SD card, so chord
sets can be written, edited and shared without building firmware - much like synth presets.

## Installing

Copy `<Name>.XML` files into a `CHORDS` folder at the root of the SD card. `Default.XML` is the
built-in set written out in this format (generated by `scripts/export_chord_libraries.py`) and is
always available as the built-in `Default` even without the file - a file with that name is
skipped by the library pad, so copy it to a new name to edit it. `Jazz.XML` is a chord-chart style
set: page one stacks the qualities a lead sheet calls for (M, -, 7, -7, M7, -7b5, 7b9, dim7 from
the bottom up) so a standard is played by walking the root columns, with extensions and altered
colours on the next pages. Edit it freely.

`Progressions.XML` is made for the layout's **split mode** (the purple pad, fourth from the bottom
of the rightmost column). Split mode turns the left seven columns into the scale degrees I-VII of
the song's key, and the six columns to the right of the dark divider into a single-note grid tuned
in fourths for soloing. Page one of `Progressions` stacks, from the bottom up, -7b5, 7, -7, -, M,
M7, 6, M9 - so a ii-V-I is column 2 on the -7 row, column 5 on the 7 row, column 1 on the M7 row.
The octave pads move the soloing hand; the horizontal encoder scrolls the chord hand by scale
steps; the vertical encoder and page column still pick the chord page.

## Choosing a library

In the chord library keyboard layout, the top pad of the rightmost column is the **library** pad.
Hold it to see the current library's name; tap it to step to the next one:
`Default` -> each file in `CHORDS/` in alphabetical order -> back to `Default`.

The pad is dim orange for Default and yellow for a file. The choice is
global (not per song) and is remembered in `SETTINGS/CommunityFeatures.XML` as
`chordLibrary="<Name>"`, so you can also set it there.

If a file cannot be read, the keyboard plays the `Default` set instead and holding the library pad
shows what went wrong, e.g. `BOSSA: BAD NOTES LIST`.

## File format

```xml
<?xml version="1.0" encoding="UTF-8"?>
<chordLibrary name="Jazz">
	<page name="Minor">
		<chord name="-7">
			<voicing notes="ROOT, MIN3, P5, MIN7" />
			<voicing name="SO WHAT" notes="ROOT, P4, MIN7, MIN10, P12" />
		</chord>
		...
	</page>
	<page name="Major">
		...
	</page>
</chordLibrary>
```

- A `page` is one screen of up to **8** chords, bottom row first. There can be up to **8** pages.
  A short page is padded with blank rows; the page `name` shows when you jump to it with the
  page column, and is optional.
- A `chord` has a `name` (shown on the display when you play it, up to about 7 characters is
  sensible) and up to **4** voicings. A chord with no voicings is a blank spacer row. The horizontal encoder steps through the voicings in the
  order given; the first one is the one that plays by default and the one used to colour the
  chord in the scale-aware modes.
- A `voicing` lists up to **7** notes as offsets from the root in `notes`, separated by commas
  or spaces, and may carry an optional `name` shown after the chord name. Offsets are either
  the interval mnemonics below or a plain number of semitones. A leading `-` puts a note below
  the root (`-OCT` adds a bass note an octave down).
- In names, a `b` directly before a digit is displayed as a flat sign (`-7b5` -> `-7♭5`); the
  UTF-8 `♭` works too. `#` is just `#`.

Interval mnemonics (semitones in brackets):

| Within the octave | | | Above the octave | |
|---|---|---|---|---|
| `ROOT` (0) | `MIN2` (1) | `MAJ2` (2) | `OCT` (12) | `MIN9` (13) |
| `MIN3` (3) | `MAJ3` (4) | `P4` (5) | `MAJ9` (14) | `MIN10` (15) |
| `AUG4` / `DIM5` (6) | `P5` (7) | `AUG5` / `MIN6` (8) | `MAJ10` (16) | `P11` (17) |
| `MAJ6` / `DIM7` (9) | `MIN7` / `DOM7` (10) | `MAJ7` (11) | `AUG11` / `DIM12` (18) | `P12` (19) |
| | | | `MIN13` (20) | `MAJ13` (21) |
| | | | `MIN14` (22) | `MAJ14` (23) |

Names are matched case-insensitively. Limits: 64 chords (8 pages), 4 voicings per chord, 7 notes
per voicing, and about 1.5 KB of text for all the names in one file.
