# Tape Saturation

A warm, analog-flavoured saturation effect that sits alongside Decimation and Bitcrush in the
Distortion menus. Where the existing distortions are deliberately digital (bit masking, sample-rate
reduction) and the stock Saturation is a plain tanh clipper, Tape emulates the way magnetic tape
softens a signal: highs compress harder than lows, peaks squash gently into a ceiling, and the
distortion is mostly low-order (2nd/3rd) harmonics rather than digital edge.

## Using it

**Tape** appears in the Distortion menu (FX section) for synths, kit rows, kit affect-entire,
audio clips, and the song master. It is a single automatable 0–50 knob, saved with presets and
songs (`tapeSaturation`), and available in the automation view for both sound and global contexts.
The 7-segment display shows `TAPE`.

Rough guide to the knob:

| Range | Behaviour |
|---|---|
| 0 | Off (bypassed entirely) |
| 1–40% | Transparent-to-gentle: unity level, peaks just start rounding, slight thickening |
| 40–75% | Clearly audible tape warmth: softened top end, 2nd/3rd harmonic body, peak compression |
| 75–100% | Rising drive: quieter sources get boosted (up to +12dB) into full tape crush |

Because the lower half is unity-gain, it works as a master-bus "glue" insert without changing the
mix level; the upper half behaves like a conventional drive knob so that quiet material (a single
drum, a low-level sample) can still reach saturation.

In the signal chain it runs immediately after Decimation and Bitcrush, so it also rounds off their
digital edges when stacked.

## DSP design

Per channel, per sample (`tape_saturation_render` in `src/deluge/plugin/fx/tape_saturation.c` - the
DSP is a tier-1 plugin kernel, see below):

```
x ──► pre-emphasis ──► × drive ──► biased tanh ──► × makeup ──► de-emphasis ──► DC blocker ──► y
        (1 − ½z⁻¹)                 (tanH2d LUT)                  1/(1 − ½z⁻¹)     (~27 Hz)
```

1. **Pre-emphasis** `u[n] = x[n]/2 − x[n−1]/4` — a first-order FIR that boosts highs ~9.5dB
   relative to DC going into the shaper (halved overall for headroom; step 4 restores it).
2. **Drive** — a q30 fine gain in [1.0, 2.0) combined with the shift built into the tanh lookup
   gives a drive that is continuous across the whole knob in 6dB-per-eighth steps.
3. **Nonlinearity** — the firmware's existing antialiased 2-D tanh table
   (`getTanHAntialiased` / `tanH2d`), plus a small drive-proportional DC bias at the input. The
   bias makes the transfer curve asymmetric, which is what produces the even (2nd) harmonic
   "warmth"; the static output offset it causes is subtracted straight back out.
4. **De-emphasis** `z[n] = v[n] + z[n−1]/2` — the exact algebraic inverse of step 1
   (`(1 − ½z⁻¹) · 1/(1 − ½z⁻¹) = 1`), so the emphasis pair is perfectly transparent when the
   shaper is linear. Under drive, the pre-emphasized highs hit the tanh harder and come back
   *darker* — this frequency-dependent compression is the core of the tape character.
5. **DC blocker** — a shift-only one-pole (`dc += (y − dc) >> 8`, ~27Hz at 44.1kHz) that removes
   the signal-dependent DC generated by the asymmetric shaping.

Cost is ~6 multiplies per sample per channel (the emphasis filters and DC blocker are shift/add
only), which is negligible next to the rest of the FX chain. State per ModControllable is four
words per channel; it is reset whenever the effect transitions from off to on.

### Plugin form

The effect is the first kernel written against the tier-1 plugin ABI (`src/deluge/plugin/README.md`):

- `plugin/fx/tape_saturation.{h,c}` - the DSP as plain C with no globals, statics or libc. Its only
  firmware dependencies, the two tanh table lookups, arrive through the `DelugePluginHostApi`
  function table; the fixed-point multiply is spelled as a 64-bit product shift (what `smmul` does),
  and the q58 makeup division is a shift-subtract loop because Cortex-A9 has no divide instruction
  and a `/` would import libgcc into a blob.
- `plugin/host/builtin_fx.h` - its `DelugeFxPlugin` descriptor (`kTapeSaturation`) including the
  param table: `{"Tape", "TAPE", "tapeSaturation", off}`. That one line is where the menu label, the
  7-segment label, the XML attribute and the preset default all come from now.
- The knob is slot 0 of the shared FX-plugin param bank (`UNPATCHED_FX_PLUGIN_PARAM_FIRST`, see
  `plugin/host/fx_plugin_bank.h`); there is no `UNPATCHED_TAPE_SATURATION` any more.
- `ModControllableAudio` holds an `FxPluginChain`, which owns a 32-byte state block per plugin and does
  the off→on reset. `processFxPlugins()` is the only host glue: hand the chain the unpatched param set
  and `getFxPluginLevelShift()` as the context's `levelShift`. `tape_saturation_is_active()` tells the
  host the knob at minimum means bypass.

The move is bit-exact: a native harness ran the pre-refactor inline code and the kernel side by side
(same deterministic table stand-ins) over 3960 random blocks - all three drive bases, every knob
boundary, block sizes 1/64/128, on/off toggling - with zero mismatches.
`plugin/check_freestanding.sh` builds the kernel as a position-independent blob (352 bytes) and
proves it has no relocations, imports or writable sections, i.e. it is ready for a tier-2 loader as is.

### Knob taper and gain staging

The three insertion points run at very different internal levels — measured during real song
playback: a lone Sound peaks around 2^20–21, kit/audio-clip summing around 2^22–23, and the song
master around 2^23–25.5. One shared calibration can never fit all three (this is why the stock
Saturation also uses different shift bases per context), so each context anchors the knob via
`getTapeSaturationDriveBase()`: **Sound 9, GlobalEffectableForClip 8, song master 4**.

On top of that base, the knob has two regimes that meet continuously at the crossover
(`base + 6`, 75% of travel):

- **Below**: small-signal gain is exactly unity (a q28 makeup multiplier cancels both the table's
  centre slope and the fine gain), and each drive step lowers the ceiling that peaks squash into
  by 6dB. Character changes; level doesn't.
- **Above**: the ceiling holds and small-signal gain instead rises 6dB per step
  (`g = 2^(sat−crossover) · fineGain`, exactly 1.0 at the boundary — no level pop while sweeping).
  This exists because a pure unity-gain/falling-ceiling design is level-dependent: internal
  levels differ hugely between a full synth patch (~2^22 peaks) and a lone cowbell sample, and
  without the rising regime quiet sources never reached the shaper at all.

The anchoring history is instructive: the first calibration, derived from a synthetic test loop,
assumed q31-nominal levels and was inaudible on hardware; an over-corrected pass was "much too
crunchy" from 10% of the knob — but only in song mode, while clips stayed silent. The eventual
diagnosis (measured live in the DelugEmu emulator via QMP guest-memory inspection, then confirmed
by rendering emulator audio to WAV and comparing crest factor and harmonics) was that both paths
worked correctly and the ~15dB level gap between contexts made any single anchoring wrong
somewhere. Hence the per-context bases.

### Fixed-point details worth knowing

- The makeup constant `1154084861100017408 = (8 / 1.998) · 2^58`, where 1.998 is the measured
  centre slope of `tanH2d` (the table is roughly `tanh(2x)/tanh(2)`). The 1-D `tanHSmall` path
  (`>> sat+2` from a ±2^31 table) and the 2-D antialiased path (`>> sat+1` from ±2^30) produce
  the same output scale, which is why the bias offset can be computed with the cheap 1-D lookup.
- The q28 makeup with a `<< 4` is deliberate: a q29 formulation overflows int32 exactly at
  fineGain = 1.0 (2^61 / 2^30 = 2^31) and wraps negative — an inverted-polarity bug that RMS-based
  tests cannot see. Caught in the native harness with an explicit sign check.
- The emphasis coefficients are exactly ½ so both filters are multiplier-free, and the de-emphasis
  IIR is unconditionally stable.

## Validation

The algorithm was developed against a native host harness that compiles the *exact* integer code
with the real firmware tables extracted from `lookuptables.cpp`, measuring per knob position:
small-signal gain (must be continuous — no pops under automation), squash ceiling, harmonic
spectrum (H2–H5 of a 441Hz sine at device-realistic levels), output polarity, and residual DC.
It also renders audition WAVs of a synth loop at several drive settings. Final measured taper:

| Knob | Small-signal gain | Ceiling (Sound, base 9) | Ceiling (song master, base 4) |
|---|---|---|---|
| 12.5% | −0.05dB | 2^23.4 | 2^28.2 |
| 37.5% | −0.15dB | 2^21.4 | 2^26.4 |
| 62.5% | −0.7dB | 2^19.4 | 2^24.4 |
| 75% | crossover | 2^18.4 | 2^23.4 |
| 100% | rising (up to ~+12dB) | 2^18.4 | 2^23.4 |

End-to-end check on a real song in the emulator: master Tape at 30/50 tamed a mix that was
touching digital full scale by ~6dB of soft peak limiting at roughly constant loudness (crest
factor 6 → 4), with no audible artifacts — the intended "bus glue" behaviour.

## Integration points

Historically the shared unpatched param touched `param.h`, `param.cpp` (display name +
`paramNameForFile`), `strings.h` + `english.json` + `seven_segment.json`, `mod_controllable_audio.*`
(default, DSP, read/write tags), `menus.cpp` (item + three Distortion menus) and `automation_view.cpp`
(both lists + counts). All of that is now derived from the plugin's param table through the FX-plugin
param bank - see `src/deluge/plugin/README.md`. What remains tape-specific is the kernel, its one-line
descriptor, and the per-context level anchoring (`getFxPluginLevelShift()`, overridden in `sound.h`
and `global_effectable_for_clip.h`).
Not mapped: MIDI follow CCs and the performance view default layout (no free slots by convention).
